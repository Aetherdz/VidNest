# VidNest UI layer (redesign)

This folder contains the redesigned UI only. The existing data layer, extractors,
repositories, providers, platform files and old `lib/features/*` screens are
untouched and still compile.

## Entry point

`lib/main.dart` now:

1. loads `FileLanguageStore` (path_provider JSON in the app support directory),
2. creates a `ProviderContainer` that overrides `languageStoreProvider`,
3. applies the saved locale to the existing `settingsProvider`,
4. runs `MaterialApp` with `AppTheme.light/dark` and `home: AppRoot()`.

`AppRoot` shows `LanguageScreen` on first launch and `AppShell` afterwards.
`go_router` is no longer mounted; `lib/features/navigation/app_router.dart` is
kept intact but unused.

## Existing hooks wired

| UI need | Existing hook |
| --- | --- |
| Analyze a URL | `mediaAnalysisProvider.notifier.analyze(url)` |
| Start a download | `DownloadRepository.startDownload(media, format)` |
| Quality list | `media.formats` from `mediaAnalysisProvider.analyze(url)` (MP3 + every MP4 quality) |
| Default quality | best video format in `media.formats`, falling back to the first audio format |
| Completed items | `completedTasksProvider` |
| Play a file | `features/player/player_screen.dart` (`PlayerScreen(task:)`) |
| Locale / theme | `settingsProvider` (`setLocale`, `setThemeMode`) |
| Logo | `core/widgets/vidnest_logo.dart` (`VidNestLogo`) |

## Thin adapters

- `adapters/language_store.dart` - first-launch flag and locale persistence.
  `MemoryLanguageStore` is the provider default so tests and the web build work
  without path_provider.
- `adapters/supported_link.dart` - clipboard/search URL detection for the
  highlighted platforms plus generic http(s) URLs.
- `adapters/storage_permission.dart` - `MethodChannel('vidnest/storage_permission')`.

### Native permission channel (not implemented yet)

The Flutter project has no permission plugin and no native handler, so the
channel currently returns `null`. The UI treats that as "unknown": it shows the
permission dialog, and an accepted in-app prompt counts for the session only.

Expected native contract:

- `hasAllFilesAccess` -> `bool`
- `requestAllFilesAccess` -> `bool` after the OS dialog closes

On Android this maps to `Environment.isExternalStorageManager()` /
`Settings.ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION` (API 30+) or
`WRITE_EXTERNAL_STORAGE` (API <= 29), plus the matching manifest entries.

## Localization

Strings live in `lib/l10n/app_{ar,en,fr}.arb` and are generated by
`flutter gen-l10n` into `lib/l10n/app_localizations*.dart`. Arabic is the
default and RTL; French and English are supplied. The language list shows more
languages, but only `ar`, `fr`, `en` are selectable today; other rows show a
localized "not available yet" snackbar.

## Known limitations

- The mock extractor never returns `thumbnailUrl`, so thumbnails use the
  offline site-glyph placeholder. `MediaThumb` renders a network image as soon
  as the data layer provides a URL.
- Downloads are still simulated by `DownloadRepository`; no file is written.
- Old screens (`features/home`, `downloads`, `library`, `settings`) are not
  used by the new shell.
